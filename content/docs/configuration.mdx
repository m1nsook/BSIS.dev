## Implemented version 1 JSON format

The first Rust builder accepts a strict JSON file:

~~~json
{
  "schema_version": 1,
  "product": {
    "id": "bsis.hello",
    "name": "BSIS Hello",
    "version": "0.1.0",
    "publisher": "BSIS"
  },
  "files": [
    { "from": "payload", "to": "app" }
  ]
}
~~~

| Field | Purpose |
| --- | --- |
| **schema_version** | Required integer, currently 1 |
| **product.id** | ASCII product identifier |
| **product.name** | Display name |
| **product.version** | Version label |
| **product.publisher** | Publisher label |
| **files[].from** | A source file or directory relative to this JSON file |
| **files[].to** | A destination relative to the installation root |

Directory mappings recursively include regular files. Destinations use forward slashes and are checked against traversal, duplicate names and invalid Windows path components.

The schema is **not stable**. The builder deliberately rejects unknown keys rather than silently ignoring unsupported installation features.

## Proposed TypeScript configuration

A future developer API could compile TypeScript into a validated native manifest, but it is **not implemented**:

~~~typescript
// Concept only: this package cannot be imported yet.
import { defineConfig } from "@bsis/core";

export default defineConfig({
  app: { name: "Example App", version: "1.0.0" },
  files: [{ from: "./dist", to: "{installDir}" }],
  ui: "./installer",
});
~~~

Features from the original vision, such as custom wizard steps, appearance settings, shortcuts, elevation and update preservation, are **not supported keys** in the current Rust JSON schema.
