BSIS (**Better NSIS**) is a design-first Windows installer framework in early development. Its goal is to let developers build a custom installation experience while a native engine handles packaging and filesystem operations.

> **Status: experimental prototype, not a public release.** The core repository is currently private. The existing Rust code can build, inspect, install and uninstall simple offline packages. UI customization, plugins and updates are plans, not released features.

## What works today

The initial Rust proof of concept implements a self-contained Windows `Setup.exe` with a Zstandard-compressed file payload.

- A strict, versioned JSON build manifest and relative file mappings.
- A Rust builder that appends the compressed payload to a Windows executable.
- A console runtime with interactive confirmation and a `--yes` automation flag.
- Integrity checks for the bundle and extracted files using SHA-256.
- Installation into a **new directory**, using a staging directory before committing files.
- A receipt-based uninstall that refuses to delete modified tracked files.

These capabilities are still being hardened and may change without compatibility guarantees.

## What's planned

Graphical installers built with web UI technologies, richer terminal experiences, silent deployment profiles, compression presets, safe Windows system integration, plugins, repair, and update workflows are **not yet implemented**.

See [Installer UI](./installer-ui/), [Plugins](./plugins/) and [Roadmap](./roadmap/) for design direction and priorities.

## Documentation conventions

This site distinguishes **Implemented** (present in the Rust prototype), **Experimental** (working but not production-ready), and **Proposed** (design work only). Snippets marked *concept only* must not be treated as working BSIS APIs.

Use the search box or `Ctrl+K` to find pages, flags and configuration fields.
