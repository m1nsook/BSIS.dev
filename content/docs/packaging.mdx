## How the prototype bundle works

The BSIS builder creates a self-contained setup executable by appending a **Zstandard-compressed file payload** to an existing native Windows PE runtime.

~~~text
BSIS-Hello-Setup.exe
├── Native Windows runtime
├── Compressed Zstandard stream
│   ├── Payload magic and manifest length
│   ├── Versioned package manifest
│   └── File content, in manifest order
└── Footer: magic, offset, length and SHA-256
~~~

The builder requires a runtime compiled for Windows; a Linux binary is not interchangeable with a Windows setup executable.

## Build and inspect

~~~powershell
cargo build --release -p bsis
cargo run -p bsis -- build --config examples/hello/bsis.json --runtime target/release/bsis.exe --output BSIS-Hello-Setup.exe
.\BSIS-Hello-Setup.exe inspect
~~~

The embedded manifest enumerates each file's relative path, byte length and SHA-256 checksum. The footer identifies the compressed stream and its digest. Inspection verifies bundle structure and digest.

## Extraction and commit

1. Validate the package metadata and target path.
2. Refuse to install into an existing directory.
3. Create a fresh staging directory beside the target.
4. Decompress and write each file, verifying its hash.
5. Store the installation receipt and rename the completed stage into place.

If extraction fails before the final rename, the temporary stage is removed. This does not provide upgrade rollback or protect against all concurrent filesystem attacks.

## Integrity and limits

The runtime checks the compressed package digest and hashes extracted files against manifest entries. Invalid destination paths, conflicting names, unsupported source links and mismatched hashes are rejected.

The current Rust manifest imposes limits on manifest bytes, file count and total declared payload size. These are defensive bounds, not proof of production readiness.

**SHA-256 is not a signature:** a malicious publisher could generate a different executable with internally consistent checksums. Authenticode signing and verification are future work.

| --- | --- | --- |
| Maximum | LZMA2 | Not implemented |
