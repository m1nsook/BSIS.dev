## Implemented: Zstandard prototype

The BSIS builder currently produces a standalone Windows setup executable by **appending a Zstandard-compressed payload** to a compiled Rust Windows PE runtime.

~~~text
Setup.exe
├── Rust Windows PE executable
├── Zstandard stream
│   ├── Payload magic + manifest length
│   ├── Versioned JSON package manifest
│   └── Sequential file contents
└── Footer: magic + offset + compressed length + SHA-256
~~~

The manifest tracks each file's relative path, byte size and SHA-256 checksum. Before extracting, the runtime checks the compressed package digest. Each extracted file is then hashed as it is written.

The format is provisional, with no published compatibility guarantee.

## Installation safety

The prototype rejects relative path traversal, invalid Windows file names and unsupported source links/reparse points. Extraction takes place in a fresh staging directory, followed by a rename into a new installation target. Existing installation targets are rejected.

Uninstall uses a receipt and refuses to delete modified tracked files. This is a safeguard against accidental data loss, not a complete threat model for adversarial concurrent filesystem changes.

## Trust and code signing

A checksum is **not a digital signature**. Authenticode signing and verification, public release packaging, safe elevation and additional Windows attack-surface testing are still needed before using BSIS for production software.
