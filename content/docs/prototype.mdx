## Implementation

| Crate | Responsibility |
| --- | --- |
| **bsis-core** | Versioned manifests, payload packaging, path validation, file installation and uninstall |
| **bsis** | Build, inspect, install, uninstall and interactive console commands |

The builder appends a Zstandard-compressed bundle to a compiled native Windows PE runtime. The runtime can run completely offline without Bun or Node.js on the target system.

## Build on Windows

With the stable Rust toolchain and the private repository checked out:

~~~powershell title="PowerShell · build the Rust prototype"
cargo test --workspace --all-targets
cargo build --release -p bsis

cargo run -p bsis -- build --config examples/hello/bsis.json --runtime target/release/bsis.exe --output BSIS-Hello-Setup.exe
~~~

A Linux-compiled binary is not a replacement for the required Windows runtime.

## Inspect and install

~~~powershell title="PowerShell · inspect, install and uninstall"
.\BSIS-Hello-Setup.exe inspect
.\BSIS-Hello-Setup.exe install --target "$env:LOCALAPPDATA\BSIS-Hello-Test" --yes
Get-Content "$env:LOCALAPPDATA\BSIS-Hello-Test\app\hello.txt"
.\BSIS-Hello-Setup.exe uninstall --target "$env:LOCALAPPDATA\BSIS-Hello-Test" --yes
~~~

Running Setup.exe without a command starts a simple interactive console prompt. Supplying --yes skips the confirmation prompt. **When started by double-clicking from Windows Explorer**, the updated prototype displays either **INSTALLATION COMPLETE** or **INSTALLATION FAILED OR CANCELLED**, then waits for you to press Enter before closing. Explicit command-line invocations still return normally without pausing.

## What happens after pressing Y?

If you accept the default path, the included hello-world sample installs to:

~~~text
%LOCALAPPDATA%\Programs\bsis.hello\app\hello.txt
~~~

To open the folder in Windows Explorer, press Win+R and paste `%LOCALAPPDATA%\Programs\bsis.hello\app`.

The example contains only `hello.txt` to verify the install/uninstall pipeline. **No desktop icon, Start Menu shortcut or app launcher is installed** yet. An **existing empty folder is now accepted**, but a folder containing files is deliberately rejected. The interactive installer explains the problem and asks for another folder rather than proceeding. The prototype does not overwrite existing files or repair installations.

The completion summary shows the actual destination and a command to uninstall it. The Setup.exe you used is required to uninstall through that command.

## Choosing an existing folder

If you manually create a folder before installation, you can select it **provided that it is empty**. For example, a freshly created `C:\Users\YourName\Desktop\MyBSISTest` directory is acceptable.

If a selected directory already contains files, the installer tells you it is **not empty**, then asks for another location. Pick a new folder name or an existing empty directory.

The engine extracts files to a temporary sibling directory first. If the chosen empty folder already exists, it temporarily moves that original folder aside and tries to restore it if committing the completed installation fails. This is an experimental installation model, not a hardened transactional update system.

## Safeguards and limits

- Installations target **new or existing empty directories**. Nonempty folders, files, symlinks and Windows reparse points are rejected. The parent directory must already exist for an explicitly provided target.
- Files are unpacked into a staging directory and verified before they are moved into place.
- A receipt lists installed files. Uninstall checks hashes and refuses to delete modified tracked files.
- The current setup executable must be retained to invoke the uninstall operation; no registered uninstaller exists yet.
- There is no GUI, UAC, shortcuts, registry integration, Windows services, signing, LZMA2, updater or public plugin API.
- SHA-256 checksums detect corruption but do **not** authenticate a publisher.

Do not use this prototype for production distribution.
