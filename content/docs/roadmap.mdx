## Initial Rust prototype

- [x] Separate Rust core and CLI crates.
- [x] Strict version 1 JSON manifest and Windows path validation.
- [x] Zstandard compressed payload appended to a Windows setup executable.
- [x] SHA-256 digest verification and receipt-based uninstall.
- [x] Installation into a new directory using staging and a final rename.
- [x] Console installation commands and unattended --yes mode.
- [x] Linux/Windows test workflows with a Windows end-to-end smoke test.

**These checkboxes describe prototype code, not a production release or public API.**

## Next: hardening

- [ ] Extended Windows compatibility and large-payload testing.
- [ ] Stable error reporting, installation journal and recovery after failures.
- [ ] Reproducible builds and pinned dependencies.
- [ ] Registered uninstaller and Windows application registration.
- [ ] Security review of privileged and concurrent filesystem operations.

## Next: developer interface

- [ ] Decide the final manifest and typed TypeScript authoring API.
- [ ] Prototype a customizable graphical installer.
- [ ] Unify graphical, interactive terminal and silent installation plans.
- [ ] Prototype safe extension points and built-in installer steps.

## Before a public release

- [ ] Add Windows shortcuts, services, registry operations and controlled UAC.
- [ ] Explore LZMA2, LZ4 and compression presets.
- [ ] Implement repairs, upgrades and transactional rollback.
- [ ] Integrate Authenticode signing and verification.
- [ ] Ship examples, reliable Windows tests and documented supported APIs.
- [ ] Make BSIS core source public when the framework is ready.

The timeline and priorities may change as implementation reveals constraints.
